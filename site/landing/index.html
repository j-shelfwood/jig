Agents do the work. You make the decisions.

An operating method for working with AI agents, and the kit that runs it: Claude Code as a team of typed agents, with an Obsidian vault as their shared memory. You don't install it by hand: your own agent interviews you and builds it.

The loop

  1. Intake. Every request becomes one line in a project tracker. Messages are read live, never copied.
  2. Shape. A line is ready for an agent when it says done when: something a command can show.
  3. Dispatch. Independent work goes out as parallel lanes to typed workers, each in its own worktree.
  4. Verify. A worker's report is a claim until it is re-derived. "Works" needs a check that could have failed.
  5. Decide. Reversible work is done. What is yours arrives as one question with a recommendation.
  6. Record. Decisions, finished tasks and the project handoff land in the vault, so no session starts from zero.
  7. Retro. Weekly, recurring friction from the agent's own transcripts becomes a hook.

Quick start

git clone https://github.com/j-shelfwood/agent-setup-blueprint.git ~/Projects/agent-setup-blueprint
cd ~/Projects/agent-setup-blueprint
claude

Then type:

Read BOOTSTRAP.md and set up my machine following it. Interview me first.

The agent takes an inventory (read only), asks you about ten questions, shows a plan table and waits for your yes. It backs up anything it would overwrite, installs, then runs checks that could fail and shows you their output.

Don't clone this inside an Obsidian vault: the templates would show up as real notes.

The principles behind it

  1. CLAUDE.md is an index, not a manual. One line per rule, pointing at the file that owns it. Content lives once.
  2. Gates are hooks, not prose. A rule that must hold (no force push, no untyped subagent, no message sent unasked) is enforced by the harness.
  3. Claims carry their instrument. verified: <command> → <result>, inferred or assumed. "Works" needs a check that could have failed.
  4. A subagent's finding is not evidence until the main agent or a verifier re-derives it.
  5. Reversible work is done; irreversible work is asked once, as a question with a recommended option. The split comes from counting which prompts were actually rejected.
  6. Two state stores: auto-memory for how to work, the vault for project state. Messages are read live, never copied.
  7. Close the loop: a weekly retro over your own transcripts turns recurring friction into hooks and doc fixes.
